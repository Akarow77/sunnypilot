# Standalone stability review — 2026-09-16

## Findings and confidence

- **Confirmed later manager-start failure caused by the recovery operation:** an
  operator command wrote `MacAcceleratorShadowEnabled` through `Params` as root.
  The resulting file was `root:root` mode `0600`; `save_bootlog()` runs as comma
  and failed in `shutil.copytree()` with `Permission denied`. The screen reported
  `Manager failed to start`. This was an operational mistake during disabling,
  not evidence that M2 inference is infeasible. Ownership was restored to
  `comma:comma` without broad permission changes; all 183 parameter files then
  passed a read check as comma. Parameter writes must use the application account.
- **Confirmed timing interference:** the production shadow hook synchronously read
  the QCOM warp to host memory before running the local policy. Readback overrun
  detection happened afterward and could not bound the first delay. The three
  saved probes recorded terminal readbacks of 13.101, 17.414, and 10.003 ms;
  40/40, 17/17, and 33/37 completed frames exceeded the 55 ms shadow deadline.
  No frame qualified. Those logs do not measure all local model deadlines.
- **Confirmed lifecycle exposure:** the persistent enable parameter was read at
  every modeld start, allowing automatic re-entry after a restart. The worker
  requested FIFO priority 5. Affinity to a little core does not prevent FIFO work
  from delaying normal-priority processes on that core.
- **Confirmed off-road transition in route76:** at monotonic time 101.536 s,
  deviceState.started became false; hardwared then reported ignition true and
  not_always_offroad false. This is an Always Offroad transition, not proof of
  power loss. Thermal state remained OK in these segments.
- **Other errors in route76:** camera ioctl errors at startup; selfdrived's 6.01 s
  initialization timeout followed by missing/slow service errors around 58.7–64.8 s;
  locationd reset its Kalman filter after a GPS position disagreement. The
  communication alerts cleared, leaving wrongGear/parkBrake, before the off-road
  transition. These segments do not establish their cause or explain later driving
  errors. They were recorded from abdbaac with a dirty checkout, not a verified
  pristine revision.
- **Separate reboot evidence, reported by the supervising session:** USB vanished
  during an ADB qlog pull while no shadow process was running; boot_id changed and
  uptime reset. After boot the stale enable flag launched shadow again. This proves
  a reboot occurred independently of an active shadow worker at that moment, but
  does not identify USB, power, kernel, or another OS fault as its cause. The reported
  Quectel teardown crash also cannot by itself establish a whole-device reboot.

## Conservative correction

The production modeld file is restored byte-for-byte to the checked-out
origin/master version. There is no accelerator parameter lookup, subprocess,
snapshot callback, retained shadow tensor, or per-frame shadow closure in its local
inference path. A stale enable parameter cannot start live capture in this revision.
The enable helper fails before any device access. Standalone benchmark workers must
demote to normal timesharing before importing their workload; failed demotion stops
startup. Existing logs, summarizers, standalone benchmarks, and UI state remain.

The initial independent audit did not deploy. The supervising recovery subsequently
restored the user's device to official master commit
`a5f44653d7f43ad57fef2f546f3916ec4cbf3c56`, retaining its experiment branch and logs.
After reboot, `IsOffroad=1` and the manager/UI processes were running, with no
manager-failure text process or shadow worker. This was checked again after three
minutes of uptime. The experiment flag was disabled before recovery and its file
was absent after the official master boot. Always Offroad was set before reboot,
but its parameter was not retained; no persistent override is claimed. The device
was physically disconnected from the vehicle and at home. These checks remove the
demonstrated local-loop interference mechanism and confirm recovery from the
permission fault; the earlier unexplained reboot still needs separate investigation.
