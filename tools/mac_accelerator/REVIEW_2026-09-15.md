# Mac M2 accelerator review — 2026-09-15

## 결론

이번 수정본은 **Big Model을 독립적인 비제어 shadow로 시험하기 위한 코드**다.
Mac 출력은 `modelV2`, `drivingModelData`, `cameraOdometry`, `modelDataV2SP` 또는
차량 제어에 게시되지 않는다. 실제 comma 3X가 분리된 상태에서 작성·검증했으며,
3X에 설치된 이전 버전은 이번 수정본과 다르다.

맥 단독 20 Hz 시험에서도 55 ms 제한시간 초과가 재현되었으므로 실차 제어용으로
승인할 수 없다. 유선 3X 왕복, QCOM host readback, 차량 부하, 전체 주행 정확도는
반드시 실제 기기에서 별도로 검증해야 한다.

## 발견하고 수정한 문제

- 기존 worker가 `modeld` 안의 daemon thread여서 GIL, 실시간 우선순위, CPU affinity를
  공유하고 로컬 policy 실행 전에 동기식 `.numpy()` readback을 했다. 모든 로컬 모델
  메시지를 먼저 게시한 뒤 snapshot하고, 네트워크·압축·로그를 별도 non-realtime
  프로세스로 옮겼다.
- 모델 준비 전 연결하여 서버의 2초 idle timeout으로 첫 카메라 프레임 전에 끊길 수
  있었다. 첫 유효 packet이 생길 때만 연결한다. 실제 3X 검증에서 calibration이
  15초보다 늦게 도착할 수 있음도 확인해 첫 프레임 고정 timeout은 제거했다. worker가
  죽으면 heartbeat TTL이, 첫 프레임 이후 멈추면 500 ms source timeout이 감지한다.
- size-one queue가 실제 카메라 누락을 숨기고 recurrent state를 그대로 이어갔다.
  원래 camera frame ID를 보존하고 누락/시간 간격 이상 때 state와 qualification을
  초기화한다. 중복·역행 프레임은 거부한다.
- handshake 직후 녹색이 되던 상태를 제거했다. Big Model 문맥을 채우는 66개 연속
  프레임과 66개 연속 제한시간 통과 뒤에만 active가 된다.
- worker가 죽어도 녹색 상태가 남을 수 있었다. 0.25초 rate-limit heartbeat와 2초
  UI TTL, 500 ms 입력 정지 감지를 추가했다.
- chunk마다 socket timeout이 새로 시작돼 느린 byte trickle이 전체 제한을 연장할 수
  있었다. header와 payload 전체에 하나의 절대 deadline을 적용했다.
- 실패를 유발한 마지막 완료 프레임과 응답 없는 실패를 보고서에서 빠뜨릴 수 있었다.
  완료 프레임 deadline miss, terminal failure, 잘린 JSONL tail을 따로 집계한다.
- 바이너리 인증키에 `.strip()`을 적용해 마지막 임의 byte가 공백일 때 키가 변할 수
  있었다. raw bytes를 그대로 읽고 앱의 키/디렉터리 권한을 0600/0700으로 검사한다.
- 오래된 로그가 무제한 쌓일 수 있었다. 한 session 32 MiB, 디렉터리 256 MiB에서
  fail-closed하며 사용자 로그를 자동 삭제하지 않는다.
- 주행 replay가 segment 경계 및 frame gap을 지나 recurrent state를 이어가고 cold
  context를 곡률 비교에 포함했다. 각 segment/gap에서 reset하고 66프레임 이전 비교를
  제외한다. 다만 timestamp 기반 카메라 정렬은 아직 구현되지 않아 결과를 accuracy
  qualification으로 표시하지 않는다.
- macOS 앱의 stdout chunk 파싱, disconnect 상태, 잘못된 저장소 추론을 수정하고
  `Mac-only test (localhost, no 3X)` 모드를 추가했다. macOS 15 최소 요구사항을 앱과
  변환 모델에 맞췄다.

## Mac-only 검증 결과

- Python/Core ML/state/UI 테스트: 45개 통과.
- 앱: 별도 review 경로에 빌드, ad-hoc 서명 검증, Info.plist lint 통과.
- 실제 Core ML/ANE + 인증 transport + 별도 shadow process, synthetic 300 frames:
  copy-to-output 평균 30.68 ms, p99 33.72 ms, 최대 57.70 ms, 55 ms 초과 1회.
- 더 긴 6,000-frame 목표 시험은 704번째 완료 프레임 부근에서 timeout을 기록하고
  fail-closed했다. 평균이 빠르더라도 지속 hard deadline은 통과하지 못했다.
- frame gap + 700 ms stall 주입: gap에서 66-frame 재준비, stall에서
  `no camera frames for 500ms`로 종료.
- server disconnect 주입: connection reset을 기록하고 shadow process 종료.
- 저장된 실제 warp 5개로 ANE와 PyTorch trace 비교: 전체 max NRMSE 0.00584,
  action max abs 0.01367 / NRMSE 0.00292. 표본 5개뿐이며 합격 기준이 없으므로
  수치 동등성 승인 결과가 아니다.
- 저장된 실주행 카메라 200프레임 Metal warp→ANE replay: 총 compute 평균 23.84 ms,
  p99 39.26 ms, 최대 81.14 ms, 55 ms 초과 1회. 66-frame cold context와 5 m/s
  이하를 제외한 35개 비교의 곡률 상관은 0.792였다. 카메라 timestamp 정렬과 desire
  history가 재현되지 않아 `accuracyQualified=false`이며 모델 우열 판단에 쓰면 안 된다.

## 해결되지 않은 항목

1. QCOM tensor `.numpy()`는 여전히 최초 1회는 동기식이다. 2 ms budget은 초과 후
   추가 복사를 막을 뿐 이미 발생한 지연을 되돌리지 못한다. 실제 3X에서 local
   model 실행/다음 프레임 지연 A/B 측정이 필요하다.
2. handshake의 SHA-256은 source ONNX에 대한 서버 선언이다. 변환된 `.mlpackage`와
   source/metadata 사이의 reproducible provenance를 암호학적으로 묶지 않는다.
3. 실제 USB-NCM scope, 재부팅 후 인터페이스 번호 변화, 3X+Mac 동시 부하, 열화 상태,
   full-route 20 Hz deadline은 이번 disconnected 검토에서 재검증할 수 없다.
4. Big Model raw curvature와 local TSFM의 postprocessed curvature 차이는 모델 우열이나
   안전성의 증거가 아니다. 카메라 timestamp 정렬, desire/action history, 충분한 여러
   주행 route, 정의된 acceptance threshold가 필요하다.
5. 이 구현은 shadow-only다. 실차 control path로 전환하는 코드는 없으며, 현재 결과로
   그런 전환을 정당화할 수 없다.
